# LUCA — Launch, Merge and Rollback Runbook

> LUCA is the live-cohort learner app: the phone-first app a cohort lives in from first look to after
> Demo Day. It covers the program page, the in-app application and fee, the interview, the offer and
> deposit, the balance, Today, Calendar, Sessions, Work, Recordings, Clans, coins, the leaderboard,
> the Sprint and Demo Day. It also includes the mentor desk and the admin console.
> It was built on the `LUCA` branch from the "LevelUp Creator Academy · Cohort 03" mockup.
> **Everything ships dark.** Nothing changes for any existing user until the switches below are turned on.

## 1. Every switch (all OFF by default)

| # | Switch | Where | What it does when ON | Default |
|---|---|---|---|---|
| 1 | `VITE_LUCA` | Build env (Vercel) **or** per-device `localStorage.VITE_LUCA = "true"` | The `/luca/*` and `/admin/luca/*` routes exist and the "LUCA cohorts" admin nav item shows. **Surface only, never authorisation**: anyone can flip it on their own device, and the server still decides what they see. | off |
| 2 | `luca_runtime_config.surface_enabled` | Database (SQL only, on purpose) | Learners can see **enabled** cohorts. While off, every LUCA cohort is visible only to admins and that cohort's linked mentors. | `false` |
| 3 | `luca_programs.enabled` | Admin console → cohort → Program → "Enabled" | This one cohort is visible to learners (needs #2 too). | `false` |
| 4 | `luca_programs.features` | Admin console → cohort → Program → Features | Per cohort: `application` (in-app 3 questions + fee; off = program page sends people to the offering page instead), `clans`, `coins`, `leaderboard`, `sprint`, `demo_day`, `whatsapp` (not built, leave off). | all on except whatsapp |
| 5 | `luca_runtime_config.reminders_enabled` | Database (SQL only) | In-app + email reminders run (every 10 minutes, pg_cron). Needs #2 too. Demo cohorts never get reminders. | `false` |
| — | The demo cohort (`is_demo = true`) | — | **Always staff-only**, whatever the switches say. Payments there are simulated; no money moves. | — |

Turning things on:

```sql
-- Switch 2: learners can see enabled LUCA cohorts
UPDATE public.luca_runtime_config SET surface_enabled = true, updated_at = now() WHERE singleton;

-- Switch 5: reminders (only after 4-reminders.sql is applied)
UPDATE public.luca_runtime_config SET reminders_enabled = true, updated_at = now() WHERE singleton;
```

Turning them off is the same statement with `false`. That is the normal "off". It takes effect on the next request, with no deploy.

## 2. Who sees what (all decided on the server)

Every LUCA screen reads through `SECURITY DEFINER` RPCs that re-check visibility and access on **every** call.
Tables are `REVOKE`d from `anon`/`authenticated`. Admins can read them, and can write only the configuration tables.

- **Staff** means admins, plus mentors linked to that cohort (Admin → cohort → Mentors → "LevelUp account").
- **Learner** means one of these:
  - an active enrolment on the cohort's offering;
  - a `cohort_applications` row at `balance_paid` or `enrolled`;
  - a row at `confirmation_paid` (the deposit is paid) whose balance isn't overdue.
- **Locked** means the deposit is paid but the balance deadline has passed. Only the balance screen opens; everything they've done is kept.
- **Applicant** means anyone with an application at an earlier stage. They see their status, interview and offer.
- **Coins** are only ever minted by the server (`luca__award`), once per action (unique ledger key).

## 3. Merging the branch into `main`

1. Review the PR. The shared-file diff is small (see §0). Everything else is new files under `src/luca/`, `supabase/`, `ops/luca/` and `public/luca/`.
2. Before merging, run the checks:
   ```bash
   npm ci
   npx tsc --noEmit -p tsconfig.app.json   # the only errors should be the pre-existing ones in AdminCourseCurriculum.tsx and UploadContext.tsx
   npx eslint src/luca                     # 0 errors (fast-refresh warnings only)
   npm run typecheck:functions             # luca-calendar and luca-link-check PASS
   npx vitest run                          # all green, including src/luca/__tests__
   npm run build
   ```
   For a deeper check, `src/luca/__tests__/screens.render.test.tsx` renders every screen against real
   room envelopes for all ten demo days. It's skipped unless `LUCA_ROOMS` points at fixtures; its header says how to make them from a scratch Postgres.
3. Merge. With `VITE_LUCA` unset, production behaves exactly as before: no LUCA route exists and no LUCA code is loaded.
4. Production already has the core, RPC and demo migrations **and their `schema_migrations` history rows**, so `supabase db push` will not re-run them.

## 4. Turning LUCA on (in this order)

1. **Database, pending pieces.** In the Supabase SQL editor, run `ops/luca/sql-editor/3-desk-and-feed.sql`, then `ops/luca/sql-editor/4-reminders.sql`. Each records its own history row. (Or `supabase db push` from `main`, which applies the two migrations.)
2. **Edge functions.**
   ```bash
   supabase functions deploy luca-calendar --no-verify-jwt
   supabase functions deploy luca-link-check
   ```
   `luca-calendar` must be `--no-verify-jwt`: calendar apps can't send a JWT, and the private per-learner token in the URL is the credential (see `config.toml`).
3. **Client flag for staff first.** On your own device, open the browser console and run `localStorage.setItem("VITE_LUCA","true")`, then reload. Open `/admin/luca` and `/luca/luca-demo`.
4. **Try the demo cohort.** Open `/luca/luca-demo/demo` (staff only) and walk the days, from "First look" to "After Demo Day". Each tap moves the whole sample cohort.
5. **Build the real cohort** in `/admin/luca`:
   1. Click "New cohort" and pick the offering. The offering sets the price, deposit and application fee. Tick "Start from the demo's copy".
   2. **Program tab:** dates, links, features, coin values, Sprint dates and Clan settings.
   3. **Copy tab:** every word learners read. The placeholders are listed on the page.
   4. Fill in the **Mentors**, **Weeks** (pre-watch and quiz), **Sessions** (Zoom links, recordings), **Assignments** (the links to hand in), **Announcements** and **Resources** tabs.
   5. Link each mentor to their LevelUp account. That gives them the mentor desk at `/luca/<slug>/desk`.
   6. Work through the **Launch check** tab until it's all green.
6. **Ship the client flag to everyone.** Set `VITE_LUCA=true` in Vercel and redeploy. The routes now exist for everyone, but every cohort is still staff-only.
7. **Open it.** Tick "Enabled" on the cohort, then flip switch 2 (§1). Learners can now reach `/luca/<slug>`.
8. **Clans.** Before day one, open the mentor desk → People → "Form Clans" (admins only). It places everyone, mixing tracks and niches. Rename Clans in the admin console. They're revealed at the start, or at `clan_config.reveal_at`.
9. **Reminders** (optional). Flip switch 5.

## 5. How the money works

LUCA reuses the existing payment path. Nothing new touches Razorpay:

- **Application fee:** `luca_apply` creates or updates the `cohort_applications` row. The app then calls `create-razorpay-order` with `payment_type: "app_fee"` and verifies through `verify-razorpay-payment`.
- **Seat deposit:** the same path with `payment_type: "confirmation"`. **Balance:** `payment_type: "balance"`. The balance on screen is `price − deposit − app fee`, the same sum `create-razorpay-order` charges.
- **Interview:** the existing Calendly integration (`calendly-slots` and `calendly-webhook`).
- **Native shells:** payments happen on the website. The Android app opens it. The iOS app only says to finish on the website, with no link or button (the Reader rule).
- **Demo cohort:** every payment is simulated (`luca_demo_advance`), so no money moves.

## 6. Reminders (after `4-reminders.sql` + switch 5)

- The job runs every 10 minutes (`luca_reminders_every_10min`). Each reminder goes to each learner at most once.
- It respects the learner's own switches in You → Reminders, and the email suppression list.

| Reminder | When |
|---|---|
| Session, a day before | 23–25 h before |
| Session, about to start | 5–20 min before |
| Deadline | 1–6 h before, if not handed in |
| Sprint | after 8 PM cohort time, if today's entry isn't in |

- Each reminder is sent in-app (the app's notifications) and by email (the existing `transactional_emails` queue, drained by `process-email-queue`).
- Nudges between clanmates and mentor verdicts are in-app notifications, sent immediately.
- To see what went out: `SELECT * FROM luca_reminders_sent ORDER BY sent_at DESC;`

## 7. Rolling back

From lightest to heaviest:

1. **One cohort:** untick "Enabled" in the admin console.
2. **All of LUCA for learners:** `UPDATE luca_runtime_config SET surface_enabled = false WHERE singleton;`. Instant, and staff keep access.
3. **Reminders:** `UPDATE luca_runtime_config SET reminders_enabled = false WHERE singleton;`
4. **The routes:** unset `VITE_LUCA` in Vercel and redeploy.
5. **Functions:** `supabase functions delete luca-calendar` and `supabase functions delete luca-link-check`.
6. **Everything in the database** (irreversible, it deletes all LUCA data): run `ops/luca/rollback.sql`. It unschedules the reminders job, drops every `luca_*` table and function, and removes the five history rows. It touches nothing outside `luca_`. `cohort_applications` rows created by in-app applications stay, because they are real applications.

## 8. Known limits, by decision

- **WhatsApp reminders:** not built. Reminders are in-app and email (`features.whatsapp` stays off).
- **Sprint view counts:** not tracked. The mockup's "12K views" tiles show the mentor's call instead.
- **"Someone passed you" reminder:** the preference exists, but the in-app toast fires only while the app is open. No email is sent.
- **Recordings:** these are unlisted YouTube (or Vimeo) links played in the app, with chapters, notes and saved progress. The link checker warns when a learner pastes a Private video.
- **Calendar:** a real subscription feed (Google, Apple, Outlook). Single sessions can also be downloaded as `.ics`.
- **The demo cohort's dates** are rewritten each time someone switches the day. Don't hand-edit them in the admin console.
- **Before `3-desk-and-feed.sql`:** in the desk, a mentor who isn't a learner sees "Assignment" instead of the assignment titles, and the demo cohort shows its sessions at shifted times of day (for example 1:48 AM instead of 6 PM). Both are fixed by that file.
